# Proceso de experiencia — Módulo de Exploración de Ocupaciones

> Versión vigente: 21 de agosto de 2026.

## 1. Propósito

El módulo busca que estudiantes de secundaria amplíen su conocimiento sobre ocupaciones, comprendan qué funciones cumplen dentro de situaciones concretas y reconozcan cuáles despiertan su curiosidad.

La **Central de Casos** presenta problemas contextualizados. El estudiante no memoriza definiciones: primero decide cómo abordar una situación y después identifica quién posee la función profesional necesaria.

La lógica vigente es:

**Problema → camino → necesidad → profesional → consecuencia → estrellas → siguiente problema → intereses**

Las estrellas brindan feedback y sensación de progreso. El objetivo educativo sigue siendo comprender ocupaciones y sus funciones.

---

## 2. Experiencia vigente dentro de un caso

### 2.1. Narrativa secuencial

Cada caso contiene una cantidad definida de problemas. Se presenta solamente el problema actual y no existen múltiples pistas abiertas al mismo tiempo.

El ciclo de cada problema es:

1. presentar una situación concreta;
2. ofrecer dos caminos posibles;
3. fijar el camino elegido;
4. mostrar la necesidad que ese camino busca resolver;
5. seleccionar un profesional del pool;
6. mostrar una consecuencia narrativa;
7. otorgar, cuando corresponde, una estrella o media estrella;
8. cerrar el problema y avanzar al siguiente.

Al avanzar, el problema anterior queda cerrado. No se puede regresar para modificar el camino ni la selección profesional.

Esta decisión reemplaza el tablero de investigación no lineal utilizado en iteraciones anteriores.

### 2.2. Sin tiempo ni recursos administrables

La experiencia no utiliza:

- presupuesto de minutos;
- unidades de recursos;
- costos numéricos;
- riesgo numérico;
- validaciones que bloqueen una decisión por falta de recursos.

El tiempo puede aparecer únicamente como parte de la narrativa, por ejemplo: “falta media hora para abrir las puertas”.

El foco es:

**qué hacer → quién puede hacerlo**

### 2.3. Presentación del problema

Cada problema contiene:

- número y título;
- descripción narrativa;
- dos caminos;
- necesidad asociada a cada camino;
- relaciones profesionales previamente definidas;
- consecuencias y feedback.

El encabezado muestra **Problema X de N**, una barra de avance y las estrellas acumuladas.

### 2.4. Selección del camino

Primero se muestran únicamente la situación y dos formas de abordarla. El estudiante escoge una.

Después de elegir:

- el camino queda fijado;
- se revela claramente qué se necesita conseguir;
- aparece el espacio para asignar un profesional;
- ya no se puede cambiar al otro camino.

La necesidad se descubre como consecuencia de la decisión y no como una lista de respuestas para marcar.

### 2.5. Pool de ocupaciones

El pool permanece disponible durante la selección profesional y contiene opciones suficientemente diversas para evitar una respuesta evidente.

Cada tarjeta incluye:

- nombre;
- sector;
- descripción breve de su función;
- icono;
- estados previos o conseguidos cuando correspondan.

Además, cada tarjeta permite abrir una **ficha completa** sin salir de la actividad. La ficha amplía el aporte contextual, tareas habituales, lugares de trabajo y habilidades de la ocupación. Consultarla no revela si la profesión es exacta o adyacente para la necesidad actual.

El sistema no indica cuál es el match esperado. Una ocupación no desaparece después de utilizarla y puede ser adecuada para más de una necesidad.

La interacción principal permite arrastrar una tarjeta hacia la necesidad. La alternativa accesible consiste en:

1. seleccionar la tarjeta mediante clic o teclado;
2. confirmar la asignación en la necesidad.

### 2.6. Adecuación profesional

Cada camino define tres relaciones posibles.

#### Match exacto

Es la ocupación que mejor responde a la necesidad elegida.

- En el primer intento resuelve el problema y otorga **1 estrella**.
- Después de un reintento resuelve el problema y otorga **0.5 estrellas**.

#### Ocupación adyacente

Tiene una relación razonable con el problema, pero no cubre la función principal.

El sistema:

- narra qué sí pudo aportar;
- explica indirectamente qué capacidad falta;
- ofrece un único reintento cuando fue la primera selección;
- desbloquea la ocupación como contacto profesional.

#### Ocupación no adecuada para la necesidad

No existe una relación útil con la intervención elegida.

Se considera no adecuada automáticamente cualquier ocupación que no esté definida como match exacto ni como ocupación adyacente para ese camino.

El sistema:

- explica brevemente por qué su campo no permite atender esa necesidad;
- no otorga estrellas;
- cierra el problema mediante apoyo adicional del equipo;
- avanza sin lenguaje de fracaso.

Esta selección no desbloquea un contacto profesional.

### 2.7. Regla del reintento

Cada problema permite como máximo:

- primer intento;
- un reintento, únicamente cuando la primera ocupación fue adyacente.

Si el reintento identifica el match exacto, se obtiene media estrella. Si vuelve a escoger una opción adyacente o no adecuada, el equipo consigue apoyo adicional y el problema se cierra sin estrellas.

No existen intentos ilimitados, vidas ni penalizaciones negativas.

### 2.8. Consecuencias

El feedback siempre muestra una acción profesional concreta. Su función es que el estudiante comprenda:

- qué consiguió la persona elegida;
- qué parte de la necesidad puede atender;
- qué especialización todavía hace falta;
- por qué una función profesional se diferencia de otra.

El feedback no se presenta como una calificación académica.

### 2.9. Sistema de estrellas

Cada problema permite obtener como máximo una estrella:

| Resultado                            | Estrellas |
| ------------------------------------ | --------: |
| Match exacto en el primer intento    |         1 |
| Match exacto después del reintento   |       0.5 |
| Problema cerrado con apoyo adicional |         0 |

NexoCon contiene cinco problemas y permite obtener un máximo de cinco estrellas.

Las estrellas se muestran durante la misión y al final. No se agregan XP, monedas, rankings, vidas, rachas ni logros adicionales.

## 3. Cierre del caso

Después del quinto problema se muestra el resultado total sobre cinco estrellas.

### 3.1. Resultado mayor a 4 estrellas

Se utiliza un mensaje positivo:

> **¡Excelente trabajo en NexoCon!**
>
> El equipo organizador quedó muy satisfecho. Tus decisiones permitieron responder adecuadamente a los principales imprevistos de la jornada.

### 3.2. Resultado de 4 estrellas o menos

Se utiliza un mensaje constructivo:

> **NexoCon logró salir adelante.**
>
> Hubo algunas situaciones en las que el equipo necesitó apoyo adicional. Sigue explorando las profesiones y sus funciones para tomar decisiones todavía mejores.

No se utiliza lenguaje de fracaso.

Superar las cuatro estrellas también desbloquea un testimonio profesional asociado al caso.

### 3.3. Selección de intereses

Después del resultado se pregunta:

> **¿Alguna de estas profesiones te llamó la atención?**

Se muestran las ocupaciones utilizadas durante la experiencia. El estudiante puede seleccionar ninguna, una o varias.

La selección se registra como interés para exploración posterior. No implica una decisión vocacional definitiva.

## 4. Estados de las ocupaciones

El prototipo diferencia los siguientes estados:

### No utilizada

La ocupación forma parte del catálogo, pero el estudiante todavía no ha trabajado significativamente con ella dentro de un caso.

### Contacto conseguido o desbloqueada

La ocupación fue utilizada como match exacto o como opción adyacente.

Significa:

> “Ya trabajaste con esta profesión dentro de un caso.”

No significa que se haya revisado su ficha completa.

### Explorada previamente

El estudiante ya realizó una actividad de exploración más profunda. Este estado se conserva aunque la ocupación vuelva a aparecer o se use en NexoCon. La ficha informativa completa está disponible para todas las ocupaciones; este estado registra el recorrido previo y no funciona como bloqueo de contenido.

### Marcada como interés

El estudiante indicó que desea conocer mejor la ocupación. Es un atributo independiente: una profesión puede estar desbloqueada o explorada y, además, marcada como interés.

El perfil simulado incluye ocupaciones nunca utilizadas, desbloqueadas, exploradas previamente y con interés previo.

## 5. Mapa de Profesiones

La navegación principal incluye la vista **Mapa de Profesiones**.

Funciona como catálogo completo de ocupaciones con identidad visual vocacional. No copia sistemas visuales de otras franquicias.

Todas las ocupaciones permanecen visibles. Cada tarjeta muestra:

- icono;
- nombre;
- sector;
- descripción breve;
- estado de contacto;
- exploración previa;
- interés, cuando corresponda.

Las ocupaciones utilizadas de forma exacta o adyacente muestran:

> **Contacto conseguido**

El mapa permite observar progresivamente con qué profesiones ya trabajó el estudiante sin ocultar las que todavía no utilizó.

Todas las tarjetas del Mapa permiten abrir la misma ficha completa disponible dentro del caso.

# 6. Testimonios profesionales

La navegación principal incluye una pestaña denominada **Testimonios**.

Este espacio presenta personas que cuentan cómo viven una profesión, qué tareas realizan, qué aprendieron y qué capacidades utilizan. Cada testimonio contiene:

- nombre de la persona;
- ocupación y rol actual;
- años de experiencia;
- frase principal;
- relato ampliado;
- aprendizajes o aspectos destacados.
- enlace al video en YouTube;
- reproductor de YouTube integrado en la plataforma.

Los testimonios aparecen bloqueados inicialmente. Cada caso puede definir qué testimonio desbloquea y bajo qué condición.

En NexoCon, obtener más de cuatro estrellas desbloquea el testimonio de una coordinadora de convenciones y eventos culturales. Al terminar la misión aparece una **alerta de logro sutil en la esquina superior izquierda**. La alerta solo informa el desbloqueo, desaparece automáticamente y no permite abandonar el cierre de la misión, porque el estudiante todavía debe seleccionar las profesiones que le interesaron.

La pestaña Testimonios presenta todos los contenidos disponibles y bloqueados. Al seleccionar un testimonio desbloqueado se abre un popup con el reproductor integrado, la información principal de la persona y un enlace externo para abrir el contenido directamente en YouTube.

Los testimonios futuros permanecen visibles como contenidos bloqueados e indican qué tipo de actividad permitirá descubrirlos.

# 8. Principios pedagógicos y de diseño

### Resolver antes que memorizar

El estudiante conoce una ocupación porque necesita comprender quién puede atender un problema.

### Función antes que nombre

La secuencia es **problema → función necesaria → profesional**, no “adivinar una carrera”.

### El feedback debe enseñar

Una selección adyacente explica su aporte y permite refinar la comprensión mediante un único reintento.

### Diferenciar profesiones sin jerarquizarlas

Exacto, adyacente y no adecuado describen el ajuste con una tarea particular. No indican prestigio ni valor general de una ocupación.

### Información breve y contextual

Las tarjetas ofrecen suficiente información para inferir funciones sin convertir la misión en lectura extensa.

### Interés no equivale a decisión vocacional

Marcar una profesión significa “esto despertó mi curiosidad”, no “esta es la carrera que debo estudiar”.

# 9. Arquitectura de contenido

La lógica de NexoCon no está escrita directamente dentro de los componentes visuales. El caso se representa mediante datos estructurados.

Cada caso puede definir:

- identificador;
- título e introducción;
- cantidad máxima de estrellas;
- problemas ordenados.

Cada problema define:

- identificador;
- número;
- título y descripción;
- dos caminos.

Cada camino define:

- necesidad;
- ocupación exacta;
- ocupaciones adyacentes;
- regla automática para considerar no adecuada cualquier ocupación que no sea exacta ni adyacente;
- resultado exacto;
- feedback y pista para el reintento;
- consecuencia no adecuada;
- cierre narrativo con apoyo adicional.

Esta estructura permite conectar posteriormente una API, CMS o generación asistida. **No se utiliza IA en la versión actual.**

Los testimonios también son datos estructurados y se relacionan con una ocupación, una fuente de desbloqueo y un caso. Cada registro incorpora la URL pública de YouTube y una URL de inserción para el reproductor interno.

# 10. Estado actual del prototipo

### 10.1. Alcance implementado

- Central de Casos con NexoCon como experiencia principal.
- Briefing narrativo de la misión.
- Cinco problemas secuenciales.
- Dos caminos fijos por problema.
- Revelación de la necesidad después de elegir el camino.
- Pool de trece ocupaciones con búsqueda.
- Asignación mediante arrastre.
- Alternativa accesible por selección y confirmación.
- Match exacto, adyacente y no adecuado.
- Único reintento condicionado a una primera selección adyacente.
- Una estrella, media estrella o cero por problema.
- Progreso “Problema X de 5” y estrellas acumuladas.
- Bloqueo narrativo de problemas anteriores.
- Resultado final positivo o constructivo según el total.
- Selección opcional de intereses después del resultado.
- Actualización de contactos profesionales.
- Vista completa Mapa de Profesiones.
- Ficha ocupacional completa disponible en la actividad y en el Mapa.
- Pestaña Testimonios con contenidos bloqueados y desbloqueados.
- Desbloqueo del testimonio de coordinación al superar cuatro estrellas en NexoCon.
- Alerta de logro no interruptiva en la esquina superior izquierda.
- Selección de testimonios desbloqueados y reproducción en popup con enlace a YouTube.
- Datos mock con estados previos.
- Estado local durante la sesión; todavía sin servidor.

### 10.2. Decisiones vigentes

- La experiencia es secuencial, no un tablero con pistas simultáneas.
- No se puede regresar a problemas cerrados.
- No existen tiempo ni recursos administrables.
- Cada problema ofrece exactamente dos caminos en NexoCon.
- El camino se fija antes de seleccionar profesional.
- El profesional se asigna a una necesidad concreta.
- Solo una selección adyacente en el primer intento habilita reintento.
- Una ocupación exacta o adyacente se desbloquea como contacto.
- Una selección no adecuada no desbloquea contacto.
- Desbloqueo, exploración previa e interés son estados diferentes.
- Las estrellas son feedback de misión, no una nota académica.
- La misión se supera al obtener más de cuatro estrellas.
- Las fichas completas son consultables antes de seleccionar un profesional.
- Los testimonios se desbloquean como recompensa de exploración y no alteran la puntuación.
- No se utilizan IA, XP, monedas, rankings, vidas ni rachas.

### 10.3. Sistema visual y componentes

Los componentes reutilizables siguen la estructura de shadcn/ui en `src/components/ui`.

La paleta, tipografía, radios y sombras continúan centralizados en:

`src/styles/Theme.css`

Las tarjetas profesionales usan iconos consistentes y colores semánticos. El sistema no depende de ilustraciones externas.

### 10.4. Convenciones de código

- Componentes, tipos y archivos TypeScript/TSX: PascalCase.
- Funciones, variables y datos: camelCase.
- Identificadores de contenido: kebab-case estable.
- Carpetas: kebab-case.
- Estilos: Tailwind y variables semánticas del tema.
- Exportaciones nombradas para módulos reutilizables.

### 10.5. Estructura del módulo

- `OccupationExplorationModule.tsx`: navegación, Central, Mapa y estado de perfiles.
- `CaseExperienceScreen.tsx`: flujo secuencial de NexoCon y cierre.
- `CaseExperienceLogic.ts`: evaluación de matches y actualización de perfiles.
- `OccupationExplorationData.ts`: caso, consecuencias, ocupaciones y perfiles mock.
- `OccupationExplorationTypes.ts`: contratos de datos independientes de la interfaz.
- `OccupationDetailDialog.tsx`: ficha completa compartida por actividad y Mapa.
- `src/components/ui`: componentes compartidos.
- `src/styles/Theme.css`: tokens visuales editables.

### 10.6. Validación manual realizada

Se comprobaron los recorridos mínimos:

1. match exacto en el primer intento → 1 estrella;
2. ocupación adyacente → feedback → match exacto → 0.5 estrellas;
3. ocupación no adecuada → cierre sin estrellas → avance;
4. cinco problemas con 5 estrellas → cierre positivo y testimonio desbloqueado;
5. cinco problemas con 0 estrellas → cierre constructivo sin lenguaje de fracaso;
6. selección de varias profesiones de interés;
7. contactos utilizados visibles con insignia en el Mapa de Profesiones;
8. ocupaciones exploradas previamente conservan su estado.

La compilación y el análisis estático terminan correctamente y la interfaz no registró errores durante estas pruebas.

### 10.7. Pendientes

- Persistencia real de estrellas, contactos e intereses en un servidor.
- Contenido multimedia definitivo para fichas y testimonios.
- Vistas completas de Mi Expediente Vocacional.
- Estados de carga, error y recuperación de sesión.
- Pruebas automatizadas de todas las combinaciones.
- Validación con estudiantes y especialistas en orientación vocacional.
- Revisión formal con teclado, lector de pantalla y contraste.
- Audio, imágenes o recursos narrativos definitivos con textos alternativos.
- Más casos con la misma estructura secuencial.
- Integración futura con API o CMS.
- Evaluación posterior de IA para generar contenido, después de validar la mecánica base.

### Decisiones históricas reemplazadas

Las iteraciones del 18 y 20 de agosto exploraron un tablero de investigación permanente, pistas simultáneas, movimientos con tiempo y recursos y consecuencias no limitadas por intentos. Estas decisiones quedan registradas como aprendizaje de diseño, pero **ya no describen la experiencia vigente**.
